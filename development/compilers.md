## Несостыковки
> [!info]- Пустых списков не существует в грамматике
> В грамматике на странице 6 список определен как:
> `List : ( Element { Element } )`
> 
> По правилам EBNF это означает: обязательная открывающая скобка, **минимум один** обязательный `Element`, затем произвольное количество элементов и закрывающая скобка. Пустой список `()` по этой грамматике является синтаксической ошибкой.
> 
> **Противоречие в тексте:**
> В спецификации пустые списки используются прямо в примерах:
> - `(func Trivial () 1)`
> - `(lambda () (1 2 3 4))`
> - Описание `cons`: *«The second argument should be a list (perhaps, empty).»*

> [!info]- Символ кавычки `'` отсутствует в синтаксисе
> В разделе специальной формы `quote` (стр. 1–2) сказано:
> > [!quote]
> > Using the single quote sign in front of an element is actually the short form of the function.
> > Примеры: `'x`, `'(plus 1 2)`, `'5`
> 
> **Противоречие в грамматике:**
> В секции *The Language F Grammar* терминал `'` не описан вовсе. Нет ни лексического токена для одинарной кавычки, ни грамматического правила для раскрытия `'Element` в `(quote Element)`. Парсер на Bison выдаст синтаксическую ошибку на первом же символе `'`.

> [!info]- Комментарии никак не специфицированы
> В примерах на страницах 2 и 3 активно используется синтаксис однострочных комментариев:
> - `(setq x (plus 1 2)) // x gets the value of 3`
> - `((myFunc -1) 1 2) // returns 3`
> 
> **Противоречие в грамматике:**
> В формальной грамматике нет ни правил для комментариев, ни символов `//`. Без явного правила игнорирования в лексере (Flex) эти символы вызовут ошибку разбора.

> [!info]- Ограничение специальной формы `prog` одним выражением
> На странице 3 приведена сигнатура:
> `( prog List Element )`
> 
> Формально она принимает ровно **два** аргумента: список переменных `List` и строго один `Element`.
> 
> **Противоречие в тексте:**
> > [!quote]
> > The second argument contains elements that are to be evaluated sequentially.
> 
> В тексте явно говорится об элементах во множественном числе (*elements*). Если `prog` принимает только один `Element`, в нем невозможно выполнить последовательность действий без упаковки их в ещё одну структуру. Сигнатура обязана быть вида `( prog List { Element } )`.

> [!info]- Взаимоисключающая семантика областей видимости `setq`
> Спецификация одновременно требует от `setq` и перезаписи внешних переменных, и создания затеняющих локальных переменных.
> 
> > [!quote] Описание setq (стр. 2)
> > «If there was not an atom with the given name in the current context then it is created and added to the context. **Otherwise, the atom that already exists in the context gets the new value.**»
> 
> > [!quote] Описание func (стр. 2)
> > «Notice that each user-defined function introduces its own local context... **If the setq form introduces an atom with the same name as an atom from an outer context, the local atom shadows the atom from the outer context.**»
> 
> **Противоречие:**
> Если внутри функции вызывается `(setq x 5)`, а переменная `x` уже существует в глобальном контексте, интерпретатор не может определить поведение:
> 1. Если следовать правилу `setq`, переменная `x` должна быть перезаписана в существующем контексте (мутация глобальной переменной).
> 2. Если следовать правилу `func`, должна быть создана новая переменная `x` в локальном контексте (затенение).

> [!info]- Запрет на вычисление имени вызываемой функции
> Спецификация ограничивает вызов функций только статическими именами:
> 
> > [!quote] Страница 1
> > «If the current element is a list, it is treated as a call to a function, whose name is the name of the first list element...»
> 
> > [!quote] Страница 4
> > «Function calls are represented as lists where the first element is atom (identifier) that is the name of the function being called.»
> 
> **Противоречие в примерах (стр. 3):**
> - `((myFunc -1) 1 2)`
> - `(((lambda (p) (cond (less p 0) plus minus)) +1 1 2)`
> 
> В обоих случаях первым элементом списка является не атом (идентификатор), а список (результат работы функции или сама лямбда). По жестким правилам страниц 1 и 4 интерпретатор обязан считать это ошибкой, так как первый элемент не является именем.

> [!info]- Логическая инверсия аргументов в описании `while`
> В описании формы `( while Element Element )` на странице 3 допущена грубая смысловая ошибка:
> 
> > [!quote]
> > «First, the **second** argument is evaluated. If the result is true then the **second** argument is evaluated, and the control from goes back for evaluating of the first argument again. In other words, the **first argument is evaluated** before each iteration.»
> 
> Текст сначала утверждает, что первым вычисляется второй аргумент (тело), а затем сам себе противоречит, заявляя, что перед каждой итерацией проверяется первый аргумент (условие).

> [!info]- Синтаксическая ошибка в примере с `lambda`
> На странице 3 приведен пример:
> `(((lambda (p) (cond (less p 0) plus minus)) +1 1 2) // returns -1`
> 
> **Анализ скобок:**
> - Открывающих скобок: 6
> - Закрывающих скобок: 5
> 
> Выражение синтаксически некорректно и содержит незакрытую скобку на верхнем уровне вызова. В зависимости от задуманной вложенности должна быть либо закрыта скобка для аргумента `+1`, либо закрыт внешний список.

> [!info]- Сравнение `null` через `equal` и `nonequal` приводит к падению
> В спецификации предикатов сравнения на странице 5 указано:
> > [!quote]
> > «After evaluation, the arguments should be of type integer, real, or boolean.»
> 
> На странице 4 зафиксировано общее правило:
> > [!quote]
> > «If the current value of an argument doesn’t meet the function requirements, the whole program stops execution.»
> 
> **Следствие:**
> Попытка проверить значение на равенство `null` вида `(equal x null)` не вернет `false`, а приведет к аварийной остановке программы, поскольку `null` не входит в список разрешенных типов (`integer`, `real`, `boolean`). Для проверки `null` остается только `isnull`, однако само поведение `equal` в отношении `null` не согласовано с концепцией литерала.

> [!info]- Отсутствие семантики для `head` и `tail` на пустом списке
> На страницах 4–5 описано:
> - `(head Element)`: возвращает первый элемент списка.
> - `(tail Element)`: возвращает список без первого элемента.
> 
> Единственное требование: *«After evaluation, the argument should be a list.»*
> Пустой список `'()` является валидным списком, но документ не определяет результат вызова `(head '())` и `(tail '())`. Варианты возврата `null`, возврата `'()` или аварийной остановки программы спецификацией не разграничены.

> [!info]- Отсутствие правил приведения типов в арифметике
> Для арифметических операций (`plus`, `minus`, `times`, `divide`) на странице 4 указано:
> > [!quote]
> > «After their evaluation, the arguments should be of an integer or real value.»
> 
> **Проблема:**
> Документ не специфицирует операцию над операндами разных типов:
> - `(plus 1 2.5)` — приводит ли целое к вещественному с результатом `3.5`?
> - Происходит ли ошибка типов из-за несовпадения операндов?
> - Допустимо ли деление целых чисел нацело в `divide` или результат `(divide 5 2)` автоматически становится `2.5`?

> [!info]- Неопределенный статус возвращаемого значения `return`
> В описании специальной формы `( return Element )` на странице 3 сказано:
> > [!quote]
> > «It evaluates its argument and interrupts the execution of the nearest enclosing form with the context.»
> 
> **Проблема:**
> В тексте отсутствует утверждение о том, что результат вычисления `Element` становится возвращаемым значением прерванной функции или формы `prog`. Сказано лишь, что выполнение прерывается. По факту семантика возврата значения опущена и оставлена на домысливание разработчику интерпретатора.

## Тесты
1. Одиночные литералы: `+42`, `-3.14`, `true`, `false`, `null`. (Проверка грамматики `Literal`).
2. Вложенные списки: `(quote (1 (2 3) 4))`.
3. Простая математика: `(plus 10 (times 2 3))` -> `16`.
4. Логика с вычислениями: `(and (less 1 5) (equal 3 3))` -> `true`.
5. Деление на ноль: `(divide 10 0)` -> (Здесь спецификация молчит. Ожидается падение (crash) интерпретатора).
6. Разбор списка: `(head (tail '(1 2 3)))` -> `2`.
7. Сборка списка: `(cons 0 '(1 2))` -> `(0 1 2)`.
8. `prog` с последовательным выполнением: `(prog (x y) (setq x 5) (setq y 10) (plus x y))` -> `15`.
9. `cond` из трех аргументов: `(cond (greater 5 10) 1 0)` -> `0`.
10. `cond` из двух аргументов (возврат null): `(cond (less 10 5) 1)` -> `null`.
11. `while` цикл: `(prog (i) (setq i 0) (while (less i 5) (setq i (plus i 1))) i)` -> `5` (Цикл `while` возвращает `null`, но `prog` вернет значение последней операции — `i`).
12. Вызов именованной функции: `(prog () (func sqr (x) (times x x)) (sqr 4))` -> `16`.
13. Лямбда-выражение на лету: `((lambda (x y) (minus x y)) 10 3)` -> `7`.
14. **Тест на Undefined Behavior (Scoping):** `(prog (a) (setq a 1) (func test () (setq a 2)) (test) a)`. (Если вернет `1` — `setq` сделал shadow. Если `2` — `setq` мутировал глобальную переменную).
15. Рекурсия (проверка изоляции локальных контекстов): `(prog () (func fact (n) (cond (lesseq n 1) 1 (times n (fact (minus n 1))))) (fact 5))` -> `120`.
